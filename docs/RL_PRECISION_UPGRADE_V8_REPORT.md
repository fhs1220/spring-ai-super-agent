# RL 精准度升级 v8 报告

## 结论

本轮完成了两件不同性质的工作：

1. 使用新冻结数据进行了第二次真实本地 DPO-LoRA 参数训练和独立盲测；
2. 在运行时增加零额外模型调用的 RLVR 候选择优，让奖励契约实际参与最终回答决策。

参数训练的独立盲测没有提升，因此适配器保持 `NOT_PROMOTED`。运行时策略升级为
`agentic-rag-v8`，可以确定性保证最终选择的已知任务契约得分不低于初稿和修订稿中的
另一份候选。v8 的真实平均质量增益仍需下一次获授权的回放验证，本轮没有调用任何线上
模型，也没有产生百炼费用。

## v8：让 RLVR 直接参与最终回答

参数更新不是让奖励影响回答的唯一方式。现有 Agent 流程本来就可能拥有两份候选：
Generate/Synthesize 初稿和 Review/Revise 修订稿。v8 在这两份候选之间加入
`deterministic-rlvr-selector-v1`：

- 引用必须存在且编号属于当前检索上下文；
- 回答必须满足普通或七天计划的长度契约；
- “不要追问”任务不能用追问替代答案；
- 三项行动、检查清单和七天计划必须具有相应结构；
- 要求标明假设、协调安排或复盘时必须覆盖对应要求；
- 明确禁止编造课程或案例时，拒绝包含推荐课程等高风险资源的候选。

选择器严格选择契约得分较高的候选；只有平分时沿用修订稿。因此它对这些可验证契约具有
单调不退化性质。它是将 RLVR 轨迹中反复出现的失败模式固化为推理时奖励选择，不修改
模型参数，也不增加模型调用。

每次发生候选择优都会写入新的 `RLVR_SELECT` 轨迹步骤：

- `selectorVersion`
- `selectedCandidate`
- `draftScore`
- `revisedScore`
- `contractNonDegrading`

同时，多 Agent `SYNTHESIZE` 步骤现在保存初稿正文。下一次回放可以重新用完整 RLVR v3
分别评分初稿、修订稿和最终候选，而不再依赖日志或只观察最终答案。

## 历史数据说明

Stage 3 的 150 个问题各有两轮真实回答。离线 oracle 每题总能选择 RLVR 较高的一轮时：

| 指标 | RLVR v3 均分 |
|---|---:|
| 第一轮 | 0.758448 |
| 第二轮 | 0.742699 |
| 随机二选一期望 | 0.750574 |
| Oracle best-of-two | 0.768378 |
| Oracle 相对第一轮 | +0.009929 |
| Oracle 相对随机 | +0.017804 |

67/150 个问题的第二轮严格优于第一轮，单题最大提升为 0.092886。这证明“候选之间存在
可选择的质量差”，但历史轨迹没有完整保存所有多 Agent 修订前初稿，所以该结果只是选择
机制的上限和设计依据，不能写成 v8 实测提升。

## 验收边界

本轮可以宣称：

- RLVR 已实际进入最终回答选择路径；
- 已知契约分数不会因 Revise 而下降；
- 选择过程可审计、可重算且不增加模型调用；
- 两次未通过盲测的 LoRA 都被正确拒绝，没有伪造参数提升。

本轮不能宣称：

- Qwen2.5-0.5B 参数已经变得更精准；
- v8 的真实 RLVR 均分已提升 0.009929；
- 已完成百炼 9B Agentic RL 训练。
