## 发现的问题：待人审，不在试跑中途修答案

1. **输出约束不足。** case02 要求四句话，两路仍添加介绍和结尾邀请；这需要人审确认
   简洁性/遵循要求评分，不能因为 Judge 给分就忽略。
2. **multi 生成与审查契约不一致。** case04 的 single 生成前收到 140–1600 字符契约，
   multi 综合提示没有同等长度/checklist。其综合初稿 5,398 字符，REVIEW 因超长重写为
   465 字符，再由确定性选择器选中；没有“六周逐周检查点”的硬检查阻止合并周次。
   multi 的 SYNTHESIZE 用时 43.315 秒、费用 ¥0.498942，REVIEW ¥0.142200；
   三个专家并行，不能把各专家时长简单相加。这个具体案例揭示额外生成/压缩开销，
   不证明哪一路语义质量更高，也不能推断总体收益。
3. **安全与引用仍需人工核验。** case03 有不必要的产品自我介绍；安全优先级、证据采集
   风险和联系对方的建议需专门审查。case05 的夜间照护假设及负担比较也应人工确认。
   Trace 有引用不代表来源支持对应断言；当前语料仅为三份关系问答，跨领域覆盖有限。
