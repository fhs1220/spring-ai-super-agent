# RLVR v3 分层 Multi-Agent 试回放报告

## 结论

2026-07-29 执行了 `agentic-rag-v5` 的 v2 分层试回放，并在第一轮引用契约修复后使用
新 Batch ID 重跑同一组 8 个种子、每题 2 轮。两批均为 16 条全新真实轨迹。运行和路由
门禁都通过，但两次最终 Release Gate 均 **未通过**，因此不得扩到 50 题。

首次失败项只有 `rlvr_violations_within_limit`：5 条轨迹触发
`missing_or_invalid_citation`。其中 2 条完全漏引，3 条使用了组合或非契约格式，例如
`[来源 1, 2, 8]`、`来源：[1, 2]`。这不是路由问题，也不应通过放宽 RLVR 门禁掩盖。

修复后重跑将引用违规从 5 条降至 2 条，RLVR 平均分从 0.714790 提升到 0.730920，
但仍不满足“违规为 0”的退出标准。剩余两条都已触发 `REVISE`，修正模型仍输出
`（来源1）`、`依据来源 1` 等非方括号格式，说明确定性修正触发有效，但格式规范化覆盖
仍不完整。

## 两轮离线修复

本次失败后只进行了离线代码修复，没有再次调用模型：

1. 将明确的组合引用规范化为逐项 `[来源 n]`，不放宽 RLVR 的合法格式；
2. 增加确定性引用契约检查：只要检索到知识库证据，最终答案必须至少包含一个合法来源，
   且所有编号必须存在于本轮上下文；
3. 即使模型 Review 返回 grounded/taskCompleted，只要引用契约未通过，也强制进入
   `REVISE`；
4. Review、Revise 轨迹记录引用契约状态，修正后仍违规时继续交由 RLVR Release Gate 拒绝；
5. 增加组合引用、漏引、越界引用和强制修正单元测试。

第一次修复能确定性处理 3 条格式变体，并为完全漏引触发额外修正。重跑证明违规从 5 条
降至 2 条，同时证明修正模型仍可能不遵守方括号格式。

重跑后继续离线增加了 `（来源n）`、`来源n`、`依据来源 n`、`参考来源 n` 及其多编号
变体的确定性规范化，并补充单元测试。该修改没有再次调用模型；是否达到 0 违规仍必须通过
下一次真实回放验证，不能用离线单测或对旧结果重新打分代替。
