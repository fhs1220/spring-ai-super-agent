# Jev System One 首次真实评测报告

## 结论

Jev 已完成 OpenRouter Decisions API 集成、影子路由、fail-open 降级、轨迹记录和反事实评测，
但本次结果未达到 80% 路由准确率发布门槛，因此保持 `SHADOW`，不接管生产路由。

本次评测最重要的工程结论不是“模型已经可以上线”，而是发布门禁成功识别了一个有潜力、
但尚未充分对齐 Cortex 实际效用目标的决策模型。

> Jev 路由数字不能代表当前实现。现已将“安全护栏”和“是否启用多 Agent”拆成独立动作，并新增
> 多 Agent precision/recall、平衡准确率及安全 precision/recall 门禁；新实现尚未用冻结 36 题
> 重跑，历史数字保持不改写。

## 故障敏感性分析

强制多 Agent 在 `debt-plan-dialogue` 上出现一次瞬时网络错误：OpenRouter 请求返回
`No route to host`。Jev 在该题选择了成功的单 Agent 路径，因此原始质量和遗憾收益被放大。

排除这一条失败的反事实后：

- 路由准确率仍从 48.57% 提升至 71.43%，提升 22.86 个百分点；
- 平均效用遗憾从 0.04340 降至 0.03510，下降 19.13%；
- 平均质量从 0.93366 变为 0.93158，变化 -0.00208，基本持平而非已证明提升。

因此可以陈述路由准确率、可用率、安全召回和决策延迟，但不能基于这一次运行声称 Jev 已
带来统计显著的质量提升或可比的成本下降。

## 发布决策

System One 发布门禁为 **FAIL**：72.22% 路由准确率低于配置的 80% 最低要求。对多 Agent
阈值执行 0.00–1.00 全范围扫描后，最高准确率仍为 72.22%，说明问题不能通过简单调阈值
解决。下一轮需要让 Jev 的判断目标更贴近 Cortex 的事后效用 oracle，并重点改善非安全
复合任务的多 Agent 识别与概率校准，然后使用同一冻结 Benchmark 重新评测。
