# Jev / Laya 审计整改记录

## 当前结论

Jev 与 Laya 仍是 Shadow 决策建议，不拥有线上回答执行权。本轮修的是评测可信度、故障
处理和标注证据链，不是训练出了新模型，也没有产生新的质量提升数据。

后续已完成固定五题开发集的真实生成/Judge pilot，5/5 配对有效、估算 ¥4.521132，
人工审批仍为 0。详见 [Pilot 报告](SYSTEM_ONE_PILOT_V1_REPORT.md)；它不调用 Jev/Laya，
也不能替代独立效果实验。

历史 36 题实验与回放保留原样；其中基于旧 utility 的 oracle、关键词质量分和不完整费用
不能直接解释为真实流量的质量/成本收益。尤其不能把那 8 个 oracle positive 当作已经
得到人工验证、固定不变的「必须多 Agent」场景。

## 已落地

| 审计问题 | 工程修复 |
| --- | --- |
| 空/非法决策被当成成功 | 严格校验问题键、类型、概率；malformed 与网络失败分别计数 |
| 费用惩罚饱和 | v2 线性 utility、独立配置及版本记录；历史回放明确 legacy |
| 只与旧路由比较 | always-single / always-multi 固定基线与配对 Bootstrap、非劣效门禁 |
| 降级 single 冒充 multi 对照 | 识别失败、空答案和 trace 中的 fallback，阻断有效性门禁/标注 |
| 标注没有完整可审核证据 | 保存双路答案、可用 trace、Judge usage、来源配置和调用账本 |
| 重启/重试可能重复付费 | 每次调用前后 checkpoint；复用成功阶段，未知结果禁止自动重试 |
| 取消或重启漏记费用 | 持久化运行快照，与样本账本归集，未知费用显式标记 |
| 自动标签未经人工确认 | 带版本的追加式审批；只导出获批 development，holdout 永不混入 |
| holdout 结果从统计泄漏 | 对外运行报告中的结果分布与样本 ID 仅来自 development |
| Shadow 只有筛选后的样本池 | 全调用分母、两路成功/失败、延迟分桶、Token 与费用未知计数 |

标注使用同一主模型单价计算生成和 Judge 的费用估算，配置变化会拒绝续用旧 checkpoint。
Judge 有超时与未退出请求互斥；标注要求 SDK 重试次数为 1。文件存储仅保证当前单实例
工作流约束，不是跨进程事务系统，也不是不可篡改的外部审计库。

## 仍需完成，不能跳过

1. 每轮冻结实验身份：模型请求标识、源码 SHA、语料 SHA、价格、质量量表与 utility 权重。
   五题 pilot 已记录这些身份，但未固定供应商模型 snapshot；`UNSPECIFIED` 只适合本地 smoke。
2. 完成五题 pilot 的人工核对：答案、引用、安全、Judge 分数与费用。之后再决定是否扩大
   到 20 条；10 元仅是估算停止阈值，不是硬消费封顶，不自动扩样。
3. 建立有代表性的独立测试集：分歧富集池适合发现困难案例，但其 holdout 不能代表全流量。
   需另行随机抽样、按语义/场景分组、时间隔离并预注册指标。
4. 校准候选策略后，与当前路由、固定 single、固定 multi 做配对验证；报告置信区间、
   稳定性、失败率、安全漏报和完整费用。未过门禁保持 Shadow，不自动上线。

额外边界：路由报告的 utility 计入决策延迟，但费用惩罚仅包含生成路径 CNY 费用；Jev 的
USD 决策估算另列，没有未经配置的汇率转换，本地 Laya 算力成本也未摊销。
`endToEndCostComparable=false` 时不得宣称端到端成本优势。全量 Shadow 指标为进程内统计，
重启清零，不是跨实例持久化时序监控。安全建议目前仍未替换原有安全处置路径。
