# Jev / Laya 上线执行计划

## 目标与当前状态

目标是让经过独立验证的 System One 候选策略决定 Single/Multi 执行模式，并在出现失败、质量回退或安全风险时回到现有路由。安全处置保持独立护栏。候选可以是 Jev、Laya 或预先定义的组合；每个候选都需要单独验证。

截至 2026-09-27，Jev/Laya 只有 Shadow 建议权；`AdaptiveMultiAgentOrchestrator.route()` 在读取建议前已确定最终路由。现有 `routing-policy` 的 SHADOW/CANARY/ACTIVE 控制的是历史轨迹策略，不是 System One。36 题冻结回放中，Jev 准确率 75.00%，Laya 69.44%，均未达到当前 80% 门槛；Laya 的开发集安全召回为 0/4。五题 v3 真实生成预检已完成，但没有调用 Jev/Laya，也没有人工批准的标签；它发现的 v6 契约漏口已在 v7 修复，尚无新版本的真实生成结果。因此当前状态为 **不允许正式接管**。

## 阶段 1：冻结候选和评测协议

- 固定待比较的 provider、模型或 checkpoint 版本、提示词、阈值、代码 SHA、语料 SHA、主模型标识、质量量表、效用权重及价格来源。开发集可选阈值，冻结集不可调参。
- 明确动作：System One 仅决定 Single/Multi；安全护栏始终可以覆盖候选，且安全决策单独记账。Jev 与 Laya 的概率不共用阈值。
- 先运行约 20 条有效配对作为流程和费用 pilot，核对双路答案、来源、安全、Judge 与人工评分的一致性；不把它当作发布结论。将实际单题费用用于制定后续实验预算及停止条件。
- 交付：不可变的实验清单、数据指纹、预注册指标和预算，记录最终候选身份。

## 阶段 2：独立效果验证

- 双路 Shadow 积累分歧样本和 agreement control；约 100 条去重样本用于开发和失误分析。另建按真实使用场景随机抽样、按语义分组并按时间隔离的独立测试集，避免把分歧富集池当成真实流量。
- 对同题强制生成 Single/Multi，核实两路均真实执行且无降级；盲评最终答案、引用和安全，记录生成、Judge、Jev API 或 Laya 本地算力的完整费用与延迟。人工复核和审批必须有原始证据链。
- 固定候选后，对独立测试集一次性比较：当前路由、always-single、always-multi、Jev、Laya，以及任何事先定义的组合。按题配对报告质量、效用、遗憾、安全漏报、可用率、成本、延迟和置信区间。样本量依预期效应及置信区间精度确定；30–50 条只作起步，不自动视为充分。
- 发布门槛沿用现有协议：accuracy ≥80%、balanced accuracy ≥70%、multi-Agent recall ≥50%、安全零漏报、遗憾不增加、质量对两种固定策略非劣、效用不劣。安全零漏报还应报告样本量和置信上界，不能把少量零事件解释为风险已消除。任何费用不完整的报告都不得声称端到端降本。
- 交付：独立、可重放的发布报告。任一门槛失败则继续 Shadow、修正候选，再用新的冻结集验证。

## 阶段 3：实现受控在线接管

- 为 System One 单独实现版本化部署状态和 `OFF → SHADOW → CANARY → ACTIVE` 状态机，避免误用历史轨迹策略的开关。只有绑定通过门禁的候选版本及报告，才允许进入 CANARY。
- 在路由器最终确定 Single/Multi 之前取得已选中候选的建议；SHADOW 仍只记录。CANARY 使用稳定散列分流并保留同时段对照组；候选超时、无效响应、不可用或部署状态不可读时回退现有路由。已识别安全风险优先走安全护栏。
- 为推荐领域与实际专家选择建立明确契约；若候选建议 Multi 而没有可执行的专家组合，应回退并记为无效决策，不能默默归功于候选。隔离评测的 FORCE_SINGLE/FORCE_MULTI 不受在线接管影响。
- 增加测试：默认关闭、影子不改路由、灰度稳定分流、安全覆盖、失败回退、错误版本拒绝、回滚、专家选择与每次路由的可追溯版本。发布接口必须限制未经授权的调用。
- 交付：默认关闭的可发布实现与自动化回归结果；代码合并本身不等于上线。

## 阶段 4：灰度、监控和正式启用

- 先以小流量 CANARY（例如 5%，再到 10%）观察同版本候选与对照组。记录完整分母、决策调用失败/超时、安全事件、最终答案质量、成本与端到端延迟；指标需跨进程持久化并与候选版本关联。仅有进程内 Shadow 计数不能作为正式监控。
- 预先固定停止和回滚阈值；质量、安全或可用率触线时自动回到 SHADOW，并核实手动回滚可用。晋升 ACTIVE 前复核样本数、质量守卫、离线/在线效用评估、费用账本和人工审批。
- 交付：灰度报告、回滚演练记录、正式部署版本及上线后观察报告。若这些条件未满足，保持 CANARY 或 SHADOW。
