## 仍需修复 / 审查

1. **通用角色介绍仍进入最终答案。** case01、case03 两路都仍有介绍或尾部邀请。
   `LoveApp.SYSTEM_PROMPT` 要求开场介绍，而通用禁套话尚未成为所有任务共有的硬契约；
   不能仅依赖生成提示里的优先级文字。应统一生成、审查、修复和候选选择的约束。
2. **安全与引用语义不由格式检查保证。** case03 Multi 在紧迫情景中夹入“先冷静1–3分钟”
   和可回复对方的信息，并将通用关系材料用作部分建议的引用。这里需要专门的安全与来源
   支撑审查；Judge 的 0.88 不是安全认证，本报告也未做完整人工安全审批。
3. **负担检查器过于依赖窄字符串格式。** case05 Single 的解释性单元格被拒绝，修复后
   仍失败但保留失败状态。下一步应明确数值/单位/周期的结构化字段，允许安全的展示性
   注释；同时不把“有表格”冒充数值合理或公平。
4. **标签 COMPLETED 不等于契约通过。** case05 Single 最终 `RLVR_SELECT` 仍显示
   “逐项契约：未通过”，配对标签却为 COMPLETED。现有流程仍要求单独真人审批；
   建议进一步让最终答案契约失败显式进入待审门禁，避免报告消费者误读状态。

这些是本轮发现的问题，未在运行途中修改代码、替换答案或补跑以改善结果。
