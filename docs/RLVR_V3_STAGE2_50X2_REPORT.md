## 结论

2026-07-29 使用 `agentic-rag-v5` 对 50 个冻结 v2 种子执行 2 轮真实回放，共得到
100/100 条完整轨迹。Single/Multi 各 50，四类业务域均得到覆盖，路由匹配 100/100，
RLVR 平均分 0.723236，达到 0.70 阈值。

本批 **未通过 Release Gate**。失败项为：

- 3 条 Single 轨迹超过种子定义的 1,600 字符上限，RLVR 硬门禁为 97/100；
- 第 43 个逻辑运行第一次执行时 `GENERATE` 超过 30 秒，显式恢复后成功，但原超时仍计入
  审计，因此超时门禁为 1。

这批结果证明 100 条分层采集、路由和断点恢复链路可运行，但 Stage 2 尚未退出，不能直接
宣称规模化 RLVR 已通过，也不能跳过 Stage 3 的训练轨迹扩充。

## 回放中修复

批处理在首次超时后暴露出编排器会直接退出的问题。本轮新增：

1. 每条成功结果继续原子写入 Manifest；
2. 重启命令时严格校验 Batch、计划指纹、策略和确定性结果前缀；
3. 已完成前缀直接从 Manifest 恢复，不再请求模型；
4. 持久化 Run 为 `FAILED`、`CANCELLED` 或 `RECOVERY_REQUIRED` 时调用显式 `/resume`；
5. 恢复前的错误和超时计入最终 Manifest 与 Release Gate，不用成功重试覆盖失败证据。

本批从 42/100 断点恢复，只重新执行失败 Run 和剩余计划，最终完成 100 条。

## 回放后离线修复

完成后没有再次调用模型。离线修复包括：

1. Generate 明确执行与种子一致的答案长度上限：七天计划 2,400，其余请求 1,600；
2. Review 的通过条件新增确定性长度契约，超长答案即使 grounded/taskCompleted 也必须修正；
3. Revise 提示明确压缩上限并保留步骤、清单、假设和引用；
4. 默认阶段级模型调用超时从 30 秒调整到 60 秒；
5. 增加断点恢复、恢复超时审计和答案长度门禁测试。

这些修改只通过离线测试，不能把当前失败 Batch 重写为通过。

### 第二轮离线修复

早停后没有再次调用模型，新增：

1. Generate、Review、Revise 统一执行完整长度区间：普通请求 140–1,600 字符，七天计划
   320–2,400 字符；
2. Review 轨迹同时记录 `minimumAnswerChars` 和 `maximumAnswerChars`，过短或过长都不能
   直接通过；
3. 回放器每写入一条结果就累计 RLVR 违规；一旦超过允许值立即固化
   `stopped_early=true` 和 `stop_reason=rlvr_violations_exceeded`，不再继续产生费用；
4. 恢复已有部分 Manifest 时先检查违规数，已经不可通过的 Batch 不会继续执行。

该部分 Batch 明确为失败证据，不能续跑后包装成通过，也不能替代新的 100/100 Stage 2
验证。完整长度契约只完成了离线测试；下一次真实验证必须使用新 Batch ID，并再次取得明确
模型调用授权。
