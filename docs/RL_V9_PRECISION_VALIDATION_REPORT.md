```text

VALIDATION: policy-v9-precision-30x2
```

`agentic-rag-v9` 在冻结高风险集上的 RLVR v3 明显优于同题历史 v7，但没有通过逐项契约、
Selector 和零超时硬门禁。因此本次实验按预先冻结规则终结，不移动阈值、不删除失败轨迹、
不把 v9 提升为已验证策略。

这不是“RL 没有效果”：平均质量提升具有正向置信区间；但它证明当前实现还不能稳定把
该提升转化为逐项零遗漏的最终回答。

## 根因

60 条轨迹按修正控制流拆分后：

| 控制流 | 轨迹 | 最终契约通过 |
|---|---:|---:|
| 初稿直接通过 | 22 | 22 |
| Reviewer 直接返回修订稿 | 23 | 0 |
| 确定性强制 Revise | 15 | 4 |

主要问题有两个：

1. Reviewer 返回 `revisedAnswer` 后，当前 Java 控制流不会再进入确定性 Revise。Reviewer
   的修订稿虽然改善了自然语言质量，却可能继续遗漏隐藏契约；这条路径贡献了 23 条失败。
2. `deterministic-rlvr-selector-v2` 使用简化契约分数选择候选，而最终评测使用完整
   RLVR v3。两个排序目标并不完全一致，因此出现 5 次选择后 RLVR 小幅下降。

最常见的缺失项是：

- 至少提供 3 个行动项：10 次；
- 显式覆盖周一、周日：各 7 次；
- 显式出现“三项/三个”等要求：7 次；
- 至少提供 7 个行动项：6 次；
- 覆盖边界或舒适度：5 次。
