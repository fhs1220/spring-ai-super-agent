## 1. 去掉相互冲突的开场要求

`LoveApp` 不再强制每次自我介绍或服务邀请。`taskFormat.noAssistantBoilerplate`
默认从普通任务推断为 true，用户明确询问助手身份时例外。
契约使用稳定修复 ID `no-assistant-boilerplate`，贯穿 single、多专家、综合、审查、修复
及候选选择；检查识别部分常见身份开场和“如果你愿意，我可以帮你……”式额外邀请。
对话话术里的“如果你愿意，我想听听你的感受”不会因这条规则失败。

这是有边界的中文启发式，不覆盖所有语言、所有改写、所有引号或 Markdown 排版。
旧三参数 `AnswerTaskFormat` 和旧 JSON 可读取；有效运行契约仍会合并当前问题推断规则。
契约版本为 `answer-verification-contract-v6`，选择器为 `deterministic-rlvr-selector-v8`。

## 2. 负担表允许注释，但要求明确单位与周期

独立的 `WorkloadComparisonCheck` 解析三类指标：学习、夜间、家务照护。每个值可为非负
数字、待填或待记录，并可带单位、周期和不超过 100 字符的括号注释。
支持小时/分钟/次/晚及天/周/月；不自动换算分钟与小时，也不把不同周期视为相同。
单位可来自指标或单元格，周期还可来自双列一致的“统计周期”行；冲突、缺失、负数、
重复指标或用一行堆多个指标关键词均失败。

```markdown
| 指标 | 我 | 伴侣 |
| --- | --- | --- |
| 学习小时/周 | 待填（用于备考） | 2小时/周（同口径） |
| 夜间次数/周 | 3（含起夜） | 待填（同口径） |
| 家务照护小时/周 | 待填（含喂养、哄睡） | 4 |
若连续两周差异超过双方约定上限，调整下一周分工。
```

仍只接受固定三列 Markdown 表和预设双方名称；任意表格、复杂范围值、跨行单元格不在范围内。
调整条件仍是有限词汇检查，并不验证阈值合理性或行动可行性；待填只是可记录模板，不是公平证明。
v2 case05 Single 原文仍不能通过：夜间单位尚未选定、未作为双方共同明确口径，因此没有为了
让旧答案“变绿”而忽略单位。对已有答案的离线检查只诊断规则，不回写旧标签或改写旧报告。

## 3. 最终契约结果不再从中文日志猜测

选择最终答案后，服务基于同一有效契约与完整检索上下文重新做确定性检查，写入：

```json
{
  "finalAnswerContract": {
    "version": "answer-verification-contract-v6",
    "passed": false,
    "missingRequirements": ["缺失的具体要求"]
  }
}
```

字段位于 `trace`，代表选中的最终答案，不是初稿或中间审查结论。旧 trace 缺少字段即未知，
不从“逐项契约：通过”之类本地化文字补推成功。前端 API 类型同步为可选字段，兼容历史响应。
两稿均不合格时在线路径仍可能返回较好的候选；本轮没有实现在线拒绝输出或安全替代答案。

## 4. 标注门禁：高 Judge 分不能盖掉失败或未知

`counterfactual-review-gate-v1` 使新运行中任一路最终契约失败或未知都进入 `REVIEW_REQUIRED`，
`humanReviewRequired=true`、`expectedMultiAgent=null`。Judge 仍保留以供对照，费用账本照常记录。
`evidence.reviewReasons` 对外提供只读原因，例如：

- `FINAL_CONTRACT_FAILED_SINGLE` / `MULTI`
- `FINAL_CONTRACT_UNKNOWN_SINGLE` / `MULTI`
- `SAFETY_AND_SOURCE_SUPPORT_REVIEW_REQUIRED`

原因不读取中文轨迹文字；即使文字声称通过，结构化结果失败仍待审。方法返回的是当前规则
派生视图，不能作为旧实验当时运行的门禁判定；历史已终态标签不自动迁移、不重写。
新版本把契约及门禁版本写入 provenance，未完成 checkpoint 不跨配置静默续跑。

安全分歧或问题命中尾随、家暴、威胁等有限风险词时，即便路由器没有分歧、Judge 很自信，
仍要求复核安全与来源支撑。共享提示也明确“来源存在”不等于“支持具体主张”，不能把通用
关系沟通材料当作具体安全处置的依据。这是审查分流与提示修复，**不是安全分类器完备性、
引用蕴含验证或医疗/法律处置能力认证**；关键词存在误报、漏报，真实安全场景仍需专门审查。

人工审批接口仍要求显式审核人、理由与版本；不会自动批准。人工可以在查看失败证据后
决定是否接受其反事实偏好标签，失败候选也可能是有效的对照证据；本轮没有代签或导出。
